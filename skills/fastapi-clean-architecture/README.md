# FastAPI Clean Architecture

Guidance for designing and reviewing FastAPI applications around clear business and technology boundaries. Domain-driven design is useful when the domain has meaningful rules; it is not a required folder layout.

## Start here

- [SKILL.md](SKILL.md) defines the workflow and rules for architecture work.
- [ARCHITECTURE_GUIDE.md](ARCHITECTURE_GUIDE.md) explains the boundaries with examples.

Keep the target repository's existing API behavior, naming, and architecture decisions. Read its `AGENTS.md`, ADRs, and a nearby feature before changing code.
